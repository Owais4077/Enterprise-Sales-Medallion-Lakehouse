# Data sources

All data is **synthetic**, produced by `data_generation/` from a fixed seed
(`config/datagen.yaml`), so every run is reproducible and nothing is private or copyrighted.
Names come from [Faker](https://faker.readthedocs.io/) locales matched to each customer's
country; products, prices, dates and amounts are generated by code in this repo.

## The three sources

| Source | Dataset | Rows (seed 42) | Access method (Phase 3) |
|---|---|---|---|
| PostgreSQL `sales` schema | customers | 5,100 | incremental on `updated_at` |
| | products | 200 | incremental on `updated_at` |
| | orders | 50,000 | incremental on `updated_at` |
| | order_items | 145,580 | incremental on `updated_at` |
| | payments | 47,711 | incremental on `updated_at` |
| REST API (`/api/v1/exchange-rates`) | exchange_rates (USD base, 10 currencies, daily) | 7,310 | paged, `updated_since` |
| CSV file `data/raw/countries/countries.csv` | countries (reference) | 20 | full load |
| JSON files `data/raw/reviews/reviews_YYYY-MM.json` | product reviews (24 monthly files) | 8,080 | new files only |

Row counts of the last generation are in `data/generation_manifest.json` (git-ignored).

## How to (re)generate

```bash
cp .env.example .env                               # once; then edit secrets
docker compose up -d postgres                      # creates schema from sql/postgres/*.sql
docker compose run --rm app python -m data_generation.generate all
docker compose up -d mock-api                      # serves data/api_source/exchange_rates.json
```

`generate files` writes CSV/JSON/API seed only. `generate postgres` TRUNCATES and reloads the
source tables in a single transaction (it refuses to run with `ENVIRONMENT=aws` unless `--force`).

## What the data looks like

- **Time window:** orders 2024-01-01 .. 2025-12-31, with growth over time, weekend lift and a
  Nov/Dec peak. Customers sign up from 2023-07-01 and only order after they exist.
- **Multi-currency:** each order is priced in its customer's currency (USD, EUR, GBP, CAD, AUD,
  INR, JPY, CHF, SEK, BRL) using the same exchange-rate series the API serves. Gold converts to
  USD with `amount / rate`.
- **Realistic shape:** order statuses depend on order age; a few heavy repeat customers and a
  long tail (for CLV); payments exist for most but not all orders (abandoned carts have none).
- **Money** is generated in integer cents and stored as `NUMERIC(.., 2)`.

## Deliberate defects (and why they get through)

PostgreSQL constraints block *structural* problems (orphan foreign keys, negative quantities,
invalid statuses, duplicate exact e-mails). They cannot block *business* problems, so those are
injected on purpose, as in real operational systems. Files and APIs have no constraints at all.

| Defect | Where | Count (seed 42) | Layer that should catch it |
|---|---|---|---|
| Same person, e-mail differs only by case | customers | 100 | Silver: deduplicate on normalised e-mail |
| Lower-case country code (`us`) | customers | 100 | Silver: standardise |
| Null city / phone | customers | 143 / 495 | Silver: null handling |
| Inconsistent category casing | products | 3 | Silver: standardise |
| `order_date` after the order was created (future-dated) | orders | 150 | Silver: invalid date, quarantine |
| Negative `total_amount` | orders | 95 | Silver: quarantine; DQ: negative sales |
| `total_amount` != sum of line items | orders | 471 | DQ: reconciliation check |
| Negative payment amount | payments | 206 | Silver: quarantine |
| Payment amount != order total | payments | 434 | DQ: reconciliation check |
| Review for a customer that does not exist | reviews (JSON) | 73 | Silver: referential integrity |
| Rating outside 1-5 | reviews (JSON) | 73 | Silver: invalid record |
| Repeated `review_id` | reviews (JSON) | 80 | Silver: deduplicate |
| Restated exchange rate (later `updated_at`) | API | 24 | Bronze/Silver: upsert on update |

The generator records the exact injected counts in the manifest, so Phase 8 can check that the
data-quality framework finds what was actually planted.

## Mock REST API

`data_generation/mock_api/app.py` (FastAPI) behaves like a small real API: `X-API-Key`
authentication, `page`/`page_size` pagination with `has_more`, `updated_since` incremental
reads (`>=`, so a boundary row may be read twice and must be upserted), a `currency` filter, and
optional failure injection (`MOCK_API_FAIL_EVERY_N`) to test client retries.
